# Capability matrix (resolver `capability-resolver-v1`)

The resolver (`coinfly.venues.capability`) binds **mode × policy × product
subtype × route × account evidence × key permissions × evidence freshness ×
local qualification × release gates** into one decision per cell. Every closed
cell names its category and the ordered blocking codes; the desktop shows the
cell for the currently selected combination (Overview → *Capability*). The
tables below are generated by `tests/venues/test_capability_matrix.py` fixtures
and reproduce exactly what the resolver returns for those inputs.

Categories: `SUPPORTED`, `BROKER_RESTRICTED` (nothing local can change it),
`ENROLLMENT_MISSING` (documented account/key workflow), `LOCAL_QUALIFICATION_MISSING`
(Coinfly gates: native signing, region channel, live gateway, paper margin),
`IMPLEMENTATION_MISSING` (no adapter), `TEMPORARY_FAILURE` (stale evidence),
`POLICY_REJECTED` (GERMANY policy narrower than the account).

## Evidence quality

* Stale evidence (`expires_at` passed) → `TEMPORARY_FAILURE` / `ACCOUNT_EVIDENCE_STALE`.
* Key without trade permission → `ENROLLMENT_MISSING` / `TRADE_PERMISSION_REQUIRED`.
* Key with transfer permission → `ENROLLMENT_MISSING` / `KEY_PERMISSIONS_EXCESSIVE_OR_MISSING` (replace the key).
* Paper derivatives without the local paper margin qualification →
  `LOCAL_QUALIFICATION_MISSING` / `PERPETUAL_MARGIN_UNCERTIFIED` (the shipped
  build qualifies it: `default_local_qualifications().paper_derivatives`).

The desktop never contains an eligibility rule of its own: it forwards the
selection and shows the worker's decision (`state.snapshot["capabilities"]`).
