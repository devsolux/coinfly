# Regional attestation and balance-gap runbook

Live execution and native credential enrollment are unavailable in this source release. The standalone read-only account collector is not wired into the desktop worker, so its balance is local simulated state or an explicitly unknown amount. This runbook explains the existing gates and the evidence an integration must supply; it does not imply that a connected Coinbase account has been verified. See [implementation status](../implementation-status.md), [ADR 0006](../adr/0006-environment-and-region-realms.md), [ADR 0007](../adr/0007-balance-coverage-and-valuation.md).

Run `coinfly doctor` for the read-only release report. A nonzero result is expected while mandatory evidence is absent. Record the exact gate code and intended authority/environment/product/profile when investigating. Do not put keys, JWTs or raw native-vault contents in reports, SQL, screenshots or diagnostic files.

| Gate or observation | What must be resolved |
|---|---|
| `REGION_UNVERIFIED` | A certified authenticated broker evidence channel must bind the real account authority, service-specific legal entity, product eligibility, portfolio scope, evidence version and current expiry/revocation status. No such channel is supplied. A locale, IP address, UI selection, unsigned document or key-permissions response is insufficient. |
| `GERMANY_SPOT_ONLY` | The application policy rejects perpetuals. GLOBAL does not authenticate different eligibility or change the account's service entity. |
| `GERMANY_BOUND_FUTURES_FORBIDDEN` | A verified Coinbase Germany GmbH binding cannot route perpetuals even with GLOBAL selected. Only new authentic service evidence can change an account binding. |
| `NATIVE_SIGNING_UNCERTIFIED` / unavailable credentials | Native binaries and signed-helper/vault behavior require qualification and reviewed release pins. The source includes bridge code, not an enrolled usable key service. |
| `LIVE_GATEWAY_UNCERTIFIED` | Independently qualify the actual account gateway, endpoints, units, order/protection semantics and authoritative reconciliation. Spot access or an `INTX` field does not prove derivatives capability. The current live factory remains unimplemented. |
| `PUBLISHER_TRUST_ROOT_MISSING` / `SIGNED_MANIFEST_MISSING` | The publisher must supply independently authenticated signed/versioned MaleCNS distribution metadata and compatible data. Do not invent a key, mirror, hash or readiness flag. Existing safety commands stay available. |

When future certified evidence expires, is revoked or becomes inconsistent, retain the prior immutable evidence and incident attribution, fence affected new work, and resolve existing obligations only under still-valid source permissions. The current release cannot automatically perform that live recovery. Do not substitute another realm, change an endpoint or broaden key permissions to make the error disappear. Missing permission for necessary exits requires the broker's authenticated operational process.

For an incomplete or inconsistent balance:

1. Inspect the immutable snapshot's environment, reporting currency, authority, included/expected scopes, coverage status, observation window and source-sequence vector. A sandbox number is simulated. An unknown value must remain unknown rather than becoming zero.
2. Check each enrolled read-only source's scope, supported account kinds, discovery status and completed pagination. A completed Advanced Trade query proves the approved query's scope only. Inaccessible vaults, other portfolios and unimplemented perpetual sources remain gaps; do not broaden a trading key to make the headline look complete.
3. Resolve account aliases using authenticated IDs and explicit source precedence. A portfolio total and its component wallet represent one pool. Equal amounts/currencies on different accounts are not duplicate evidence. Preserve ambiguous observations and discrepancies for investigation.
4. Check account and mark ages, missing FX, stablecoin marks, liabilities, funding/fee settlement and transfer provenance. For delayed transfer legs use proven clearing evidence; do not book snapshot differences as trading profit. Normalize equity-inclusive collateral before adding unsettled perpetual P&L once.
5. Publish the observed subtotal with its gaps. `complete_observed_equity` remains absent unless completeness is verified. Show locks and custody restrictions separately, and obtain active-book spendable funds from the execution risk path. An observed vault asset does not authorize withdrawal, transfer or trading.
6. Reconcile and refresh through the approved source when available. The current desktop worker has no Coinbase enrollment/polling integration, so an absent total cannot be repaired by a UI toggle or refresh alone. Implement and certify that integration before claiming a populated consolidated Coinbase balance.

`PARTIAL` indicates a known scope, access, page or valuation gap. `STALE` identifies aged account observations or marks. `INCONSISTENT` identifies a recognized reconciliation, identity or timing conflict. `UNKNOWN_UNIVERSE` means the available evidence cannot establish whether all relevant accounts are known, including when universe evidence has expired. Constraint completeness is independent: unverified lock overlap can leave lock/custody/pending metrics absent while equity coverage is `COMPLETE_VERIFIED`. That status still describes its explicit authority/environment/universe and observation window, not unrestricted spendability or a universal exchange-wide atomic snapshot.
